# FinTrack — личные финансы

Полноценная первая версия веб-приложения на React + TypeScript + Vite + Supabase. Включает настоящую email/password-аутентификацию, сохранение операций в PostgreSQL, бюджеты и RLS-политики для изоляции данных пользователей.

## Возможности

- Регистрация, вход, выход, сброс пароля через Supabase Auth.
- Личный кабинет: общий баланс, доходы и расходы за текущий месяц, сравнение с предыдущим месяцем.
- График денежного потока и диаграмма расходов по категориям.
- Создание, изменение и удаление операций.
- Поиск, фильтрация по типу/категории/датам.
- Месячные бюджеты, прогресс и предупреждение при использовании 80% лимита или его превышении.
- Аналитика за выбранный месяц.
- Адаптивная тёмная тема.
- Все финансовые записи изолированы RLS-политиками по `auth.uid()`.

## 1. Создайте проект Supabase

1. Откройте [Supabase](https://supabase.com/) и войдите или создайте аккаунт.
2. Создайте новый проект (Organization → New project), задайте имя `fintrack` и сохраните пароль базы в менеджере паролей.
3. Дождитесь готовности проекта.
4. В меню проекта откройте **SQL Editor → New query**.
5. Откройте файл `supabase/schema.sql` из этого проекта, скопируйте его целиком в редактор и нажмите **Run**. Это создаст таблицы, индексы и политики Row Level Security.
6. Перейдите в **Project Settings → API** (в некоторых версиях интерфейса — **Data API / API Keys**). Скопируйте Project URL и **publishable key** (или legacy `anon` key). Не используйте `service_role` / secret key в браузере.

## 2. Настройте приложение локально

Требуется Node.js 20+.

```bash
npm install
cp .env.example .env
```

Откройте `.env` и заполните:

```env
VITE_SUPABASE_URL=https://ВАШ-ПРОЕКТ.supabase.co
VITE_SUPABASE_ANON_KEY=ВАШ_PUBLIC_ANON_ИЛИ_PUBLISHABLE_KEY
```

Затем запустите:

```bash
npm run dev
```

Откройте адрес, который покажет Vite (обычно `http://localhost:5173`).

## 3. Настройте email-аутентификацию

В Supabase откройте **Authentication → URL Configuration**:

- **Site URL** — URL приложения (локально `http://localhost:5173`, после публикации — ваш публичный домен).
- **Redirect URLs** — добавьте локальный URL и публичный URL приложения, например `http://localhost:5173/**` и `https://ВАШ-ДОМЕН/**`.

В **Authentication → Providers → Email** проверьте, что включён Email provider. Для сброса пароля настройте URL перенаправления. В зависимости от настроек проекта Supabase подтверждение email может требоваться до первого входа. Для реального публичного запуска рекомендуется настроить SMTP-провайдера, чтобы письма регистрации и сброса пароля надёжно доставлялись пользователям.

## 4. Публикация в интернете (Vercel)

1. Загрузите папку проекта в свой GitHub-репозиторий.
2. Откройте [Vercel](https://vercel.com/) и выберите **Add New → Project**, затем импортируйте репозиторий.
3. Framework preset: **Vite**. Команда сборки: `npm run build`. Output directory: `dist`.
4. В настройках проекта Vercel → **Settings → Environment Variables** добавьте `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` с теми же значениями, что в `.env`. Не добавляйте `service_role`.
5. Нажмите **Deploy**.
6. Скопируйте выданный домен `*.vercel.app`, вернитесь в Supabase → **Authentication → URL Configuration** и установите этот адрес как Site URL и добавьте в Redirect URLs.
7. После изменения переменных окружения запустите новый redeploy.

Альтернативно можно публиковать статическую сборку на Netlify или любом статическом хостинге, поддерживающем SPA fallback.

## 5. Проверка перед запуском

- [ ] Создать аккаунт с новым email.
- [ ] Подтвердить email, если подтверждение включено в Supabase.
- [ ] Войти и добавить доход.
- [ ] Добавить расход, отредактировать и удалить запись.
- [ ] Обновить страницу: записи должны остаться.
- [ ] Выйти и войти снова: записи должны остаться.
- [ ] Создать второй тестовый аккаунт: он не должен видеть операции первого пользователя.
- [ ] Задать бюджет, добавить расходы и проверить индикатор бюджета.
- [ ] Проверить восстановление пароля с реальной почтой.
- [ ] В Supabase → Table Editor проверить, что RLS включён у `transactions` и `budgets`.

## Безопасность и важные замечания

- В клиенте используется только публичный ключ Supabase. Безопасность доступа обеспечивается RLS в базе, а не сокрытием публичного ключа.
- Никогда не вставляйте `service_role` или другой секретный ключ в `.env` с префиксом `VITE_`, клиентский код, GitHub или браузер.
- `user_id` отправляется приложением, но база дополнительно проверяет его через `auth.uid()` в RLS-политиках. Клиент не может получить записи другого пользователя обычными запросами.
- Приложение сохраняет суммы в EUR. Если нужна другая валюта, её форматирование и валюту в `money()` стоит изменить до начала реального использования.
- Этот проект подготовлен к публикации, но не опубликован автоматически: для реальной регистрации и хранения данных нужны ваш проект Supabase, переменные окружения и аккаунт хостинга. До их настройки форма входа намеренно не работает как демо.
- Перед широким публичным запуском настройте SMTP/лимиты auth, проверьте домен и политику конфиденциальности, включите мониторинг ошибок и выполните сценарии проверки выше.
